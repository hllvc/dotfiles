# crons

Scheduled user-level jobs. Each cron is a directory under `crons/` with its own runtime entrypoint, LaunchAgent plist (in [`.config/launch-agents/`](../../../.config/launch-agents/)), and — optionally — an `install.sh` for one-time system setup.

[Back to scripts](../)

## Contract

A cron directory is picked up by `./dotctl crons install` if it contains an `install.sh`. Scripts are invoked with `cwd` set to their own directory, so `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` works as expected.

Drop a new folder with an `install.sh` and `dotctl` will run it on the next install pass — no edit to `dotctl` needed.

The LaunchAgent side is orthogonal: any `*.plist` in `.config/launch-agents/` is loaded by `./dotctl agents load`; `./dotctl agents disable <name>` turns one off persistently (launchd override, survives `load`/`all`/reboot), `enable` undoes it.

`_lib/` holds bash snippets shared between crons (`log.sh` for the bordered-block logger, `notify.sh` for `alerter` wrappers, `warning.png` as the default alert icon). The upgrade sequence shared with `brewup` is in [`../lib/`](../lib/), which is for scripts that aren't crons. It has no `install.sh` so `dotctl crons install` skips it.

## Crons

| Directory | Description |
|-----------|-------------|
| `homebrew-update/` | Runs daily at 10:00 via `com.hllvc.homebrew-update` LaunchAgent (currently disabled; `brewup` does the same by hand). Skips on battery or offline. Runs the shared sequence in [`../lib/brew-upgrade.sh`](../lib/brew-upgrade.sh), also used by `brewup`: `brew update`, `dotctl versions pins` and `auto` (brew-pinned tools get the upgrades their `.versions` pin level allows), `brew upgrade`, `upgrade --cask --greedy`, `autoremove`, `cleanup -s`, then `link-skills.sh`, which re-points `~/.claude/skills/<skill>` at the skill the current cask version ships (resolved via `/opt/homebrew/bin/<bin>`; also run by `dotctl stow`). Logs to `~/Library/Logs/com.hllvc.homebrew-update/main.log`; sticky alert naming the failed steps. `install.sh` writes a `sudoers.d` snippet (NOPASSWD for installer/file-ops) and a `newsyslog.d` rotation rule. |
| `memory-pressure/` | Samples `memory_pressure` every 5 minutes via `com.hllvc.memory-pressure` LaunchAgent; logs to `~/Library/Logs/com.hllvc.memory-pressure/main.log` and fires an `alerter` notification below 40% free. `install.sh` writes a `newsyslog.d` rotation rule (requires sudo). |
| `tmux-autosave/` | Idle-gated tmux session saver. Three save triggers: (1) `com.hllvc.tmux-autosave` timer fires every 30 min — saves when HID idle ≥ 30 s, force-saves after 90 min; (2) `~/.sleep` run by `sleepwatcher` (`com.hllvc.sleepwatcher`) before sleep/hibernate; (3) `daemon.sh` kept alive by `com.hllvc.tmux-shutdown-save` catches launchd `SIGTERM` on shutdown/reboot. All paths call `entrypoint.sh --force` (sleep/shutdown) or the normal idle-gated path (timer). Logs to `~/Library/Logs/com.hllvc.tmux-autosave/main.log`. Replaces `@continuum-save-interval` (disabled in `.tmux.conf`). Requires `brew install sleepwatcher`. `install.sh` writes a `newsyslog.d` rotation rule (requires sudo). |
| `tmux-warmup/` | Pre-starts the `work` and `personal` tmux servers at login (one plist per socket: `com.hllvc.{work,personal}.tmux`) so `tmux-continuum` auto-restore runs before the user attaches. Verifies the socket is up, counts restored sessions, logs to `~/Library/Logs/com.hllvc.tmux-warmup/main.log`, and fires an `alerter` notification on each launch (sticky on failure). `install.sh` writes a `newsyslog.d` rotation rule (requires sudo). |
| `versions-review/` | Daily at 10:30 via `com.hllvc.versions-review` LaunchAgent (also run by `brewup`): for each tool in `.versions` that drifted from its tested version (or has a brew-pinned upgrade waiting), `review.sh` has Claude Haiku classify every change in the range twice, with read-only tools, and a fixed rule turns that into a verdict. No config impact (both runs agree): `dotctl versions accept` plus a signed commit on `main`, silently. Anything else, and always for `review=strict` tools: Claude Opus drafts a plan in a session that waits in a window of the `updates` tmux session (personal socket, set up by `updates.sh`), with a "Plan ready" notification. Results are cached per tool and range in `~/Library/Caches/com.hllvc.versions-review/`; logs in `~/Library/Logs/com.hllvc.versions-review/`. `triage.md`, `plan.md` and `verdict.schema.json` are the prompts and output schema; `review.sh <tool>` (via `dotctl versions review`) runs it by hand, and the only way to run `review=manual` tools. Details: root README, "Tool Versions". `install.sh` creates the log and cache dirs and checks for `claude`, `jq` and `alerter`. |
| `wifi-watchdog/` | Recovers the ISP router's silent 5 GHz stream collapse on the **`hllvc`** network by bouncing the radio; runs every 30 s via `com.hllvc.wifi-watchdog` plus on network change (`WatchPaths`). Bounces only when all three hold for 3 consecutive samples — Tx Rate < 300 Mbps, RSSI better than −70 dBm, NSS ≤ 1 — then confirms it rejoined the same SSID and cools down 60 s. Scoped by SSID and independent of the default route, but NSS 0 cannot be judged and never acts: behind Ethernet it logs `IDLE` (caught once Wi-Fi carries traffic again); as the default route it logs `NO READING`, since the driver's rate stats can freeze at NSS 0 for hours on a live link. Wi-Fi left off is left alone. Needs `sudo -n wdutil info` (the only source reporting NSS) from the `sudoers.d` rule `install.sh` writes; without it, logs `NO SOURCE` and refuses to bounce. Logs to `~/Library/Logs/com.hllvc.wifi-watchdog/main.log` and `logger`. `--dry-run` uses its own state file, `--status` prints the link. `install.sh` also writes a `newsyslog.d` rule (requires sudo). |
